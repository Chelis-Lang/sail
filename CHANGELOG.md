# Changelog

All notable user-visible changes are recorded here. The project follows
semantic versioning once the API is published.

## Unreleased

- Make fault-test timeout cleanup independent of a stalled output-buffer lock.
  Incomplete reader retirement now fails explicitly; solver deadlines and reply
  checks remain unchanged. This does not identify earlier solver-test timeouts.

- Reuse validated ordinary Cargo build-script contracts across compatible
  compiler-family selectors. Consume each shared generation before mutation,
  recheck after input guards begin, and retain every output unit. Unavailable
  contracts still force cleaning; exact proof contexts and receipts stay private.
  Whole-loop performance validation remains pending.

- Retain freshly validated ordinary dependency contracts after a fully observed
  Current negative full verification. Require complete normal compiler outcomes
  and pre-existing input coverage; compiler errors, incomplete runs and uncertain
  inputs still withdraw the generation. Failed proofs and successful-receipt
  rules are unchanged. Product validation remains pending.

- Avoid repeated Linux runtime identity parsing when the original continuous
  lease binds both exact sidecar paths. Missing coverage retains the original
  parse; all per-read freshness checks remain. No live reader latency gain is
  claimed from the component comparison.

- Retained-result output owners use one bounded daemon constructor,
  shared frame-cache admission and original complete read/hash fallback. Exact
  input/runtime freshness remains independent. The implementation passed 35
  affected native tests and strict checks; installed activation and the original
  live reader acceptance remain pending.

- Add a Linux primitive for continuously guarded retained output digests. It
  certifies complete output bytes only; the daemon retains its original read/hash
  fallback and independent input freshness checks. No live reader gain is
  claimed until complete validation costs and original gates pass.
- Share managed Cargo dependency artifacts across source-engine focus selectors,
  while keeping exact proof contexts and receipts separate. Serialize shared
  target mutations and retain fresh verification of selected repair packages.
  Select compatible optional sysroot hints across those selectors while keeping
  independent caller guards and hashing fallback. Product and performance
  validation of these changes remain pending.

- Select the qualified optional source engine with conservative imported-range
  absence handling and preparation retirement acknowledgement. Its original
  thirteen-stage source qualification passes, including genuine reuse across
  edits and three complete HumanEval revisions. Publish a digest-pinned prebuilt
  Linux runtime for CI; M7 product integration and performance remain pending.

- Optimize Linux managed input path checks using owned descriptors, with exact
  pathname/inode checks and the existing conservative fallback. Reader latency
  acceptance remains under validation.
- Bind queued timeout-observation descendants by PID birth ticks and support a
  previously recorded root identity. Keep bounded all-task traversal and
  original timeout/cleanup behavior; no observation certifies a proof.

- Charge cached complete-result frame families by retained buffer capacity, and
  keep their charge through an in-flight response after eviction. When the
  128 MiB quota is unavailable, return the complete response without caching it.
  Reserve fixed index, control and retirement headroom inside that ceiling;
  uncached output releases the two unselected currentness variants.

- Move owned MCP result graphs through response envelopes and encode complete
  replies before taking the stdout write lock. Preserve complete text and
  structured payloads, atomic frames and cancellation through publication.
- Add optional bounded job RPC stage diagnostics, with no default stage clocks
  or trace I/O. Keep complete output seals, fresh currentness and full responses
  on every read; retain the original failed live Result latency separately.

- Coordinate the sysroot handoff test fixture's first preparation hint with
  maintenance startup. Keep production busy refusal, original handoff checks
  and deadlines; release and join fixture workers on assertion unwind.

- Stop fault-fixture maintenance when a concurrent session assertion unwinds,
  so cleanup cannot hide the original failure behind a scoped thread join.
  Retain the original solver checks and deadlines, with direct phase diagnostics.

- Move shared-cache trust/configuration filesystem work onto owned helpers,
  including startup and refresh. Keep the original lookup deadline and signing
  checks; status can omit unavailable optional snapshots instead of waiting for
  filesystem or client construction.

- Retain the first failed proof-time barrier and existing namespace reason in
  managed coverage notes. Preserve original Unknown proof notes when reading a
  job instead of attributing that uncertainty to a later projection failure.
  Distinguish sysroot namespace and explicit-file observation failures and
  retain their existing reasons without additional probes.

- Provide fresh service-owned Linux product installation with exact byte grants,
  private executable modes and no existing-destination replacement. Record
  ownership/capability setup prerequisites in the reader controller; keep complete
  production freshness checks and original acceptance bounds unchanged.

- Reuse an unchanged loopback HTTP connection pool after fresh complete
  configuration validation, avoiding repeated runtime construction on reload.
  Keep credential/CA rotation, timeout changes, HTTPS root refresh and signature
  checks; lookup deadlines remain unchanged.
  Reject private CA files containing no PEM certificates instead of silently
  adding no private trust roots.

- Stage automatic Linux sysroot-digest reuse through a trusted local daemon.
  Keep overlapping original caller guards, complete inventory checks and fresh
  executable identities; fall back to local hashing on any unavailable or
  invalid handoff. Bound background ownership and aggregate optional RPC work.
  Bind arbitrary environment bytes as sorted pairs, with bounded streaming
  encoding, so staged reuse is not silently disabled by JSON object-key rules.
  Wait for optional RPC socket readiness instead of sleeping between retries;
  retain the original absolute budget and reject late or invalid replies.

- Invalidate retained Linux proof and sysroot-digest coverage on kernel mount
  events, including a bind mount restored before the next check. Preserve
  existing file guards and conservative fallback; test real mount restoration
  in an isolated namespace as part of the solver suite.

- Let shared-cache lookup helpers wait for concurrent HTTP setup within the
  existing lookup budget. Preserve bounded fallback, credential reload and trust
  checks; avoid an immediate miss when the configured client is still starting.

- Start configured HTTP client initialization asynchronously when the daemon
  opens its cache, reducing cold remote misses without a startup wait. Preserve
  lookup deadlines, signature and trust checks, bounded constructor ownership,
  and the lightweight unconfigured local path.

- Index current canonical native watches during Linux observer setup. Preserve
  descriptor replacement across hardlink aliases, coverage checks and watch caps.

- Avoid scanning every tracked input for each Linux namespace event. Preserve
  exact path relationships, explicit output-directory inputs, complete native
  coverage and all existing freshness limits.

- Stage complete-result decoding reuse in ordinary persistent Rust SDK clients:
  retain the first validated frame without cloning its graph, then promote after
  an identical fresh response. Keep complete RPC validation and independent
  returned reports, with bounded retention and an explicit uncached constructor.

- Retain raw partial stdout and stderr for timed-out corpus verification units.
  The timeout remains an infrastructure error and kills the verifier process
  group; partial output never becomes a completed proof or conformance result.
- Wake waiting freshness readers on owner publication while retaining the same
  absolute wait limit, entry-time eligibility and complete input/lease checks.

- Reduce Linux kernel lease inventory parsing work while preserving exact owner,
  descriptor and row checks, both validation sweeps and all currentness bounds.

- Reuse bounded service clients for MCP job status, result and counterexample
  reads while receiving a fresh reply on every call. Preserve source currentness,
  report schemas, CLI fallback errors and verification/cancellation ownership.

- Add explicit bounded complete-result decoding reuse for persistent Rust SDK
  clients. Every call still reads a complete fresh RPC response; single-use
  clients keep ordinary decoding. Changed or malformed frames cannot reuse a
  prior success.
- Add an SDK job-call path with joined cancellation and an absolute five-second
  transport budget. Refuse late responses and distinguish pre-RPC connection
  failures from failures that must not trigger another transport attempt.

- Coalesce overlapping freshness readers from caller entry while retaining exact
  namespace, runtime and lease validation. Currentness remains separate from a
  solver verdict and does not use an age-based grace period.

- Optimize strict shared-signature arithmetic in development and test builds;
  retain the same trust checks, lookup deadlines and release configuration.

- Keep late HTTP configuration initialization inside bounded lookup helpers;
  client startup and retirement cannot block status or shared lookup callers.
  Preserve trusted-entry checks, credential reloads and the existing deadlines.

- Deliver verified shared-cache replies directly to concurrent readers, without
  waiting for the initiating caller to resume; retain bounded misses and all
  signature, query and solver identity checks.

- Bind preparation counters to complete normally terminated engine evidence;
  exclude failed attempts and retained journals after stock fallback.

- Require an explicit normal-termination marker and complete structured full
  result before retaining optional-engine output. Panic, signal, malformed or
  legacy terminal events fall back to stock; preserve ordinary failure reports,
  failed engine output, stock diagnostics and actual fallback process counts.

- Keep Cargo output exclusions effective when native watch events use canonical
  paths and configuration uses a symlink alias, including not-yet-created paths.

- Reuse run-local sysroot byte hashes on Linux only while kernel leases and
  precise namespace observation remain continuously owned from the first hash
  through receipt publication. Lost coverage forces fresh byte checks and
  unavailable current evidence.

- Validate optional-engine artifacts in the same byte-hashing phase as the
  verification context, retaining complete inventory and manifest checks before
  any engine executable starts.

- Retain optional per-driver preparation counters with separate batch-local and
  persistent reuse; unavailable telemetry is distinct from observed zero hits.

- Decline ambiguous trait-implementation obligation joins when Verus repeats a
  friendly function name; preserve full results and partial-attribution evidence.

- Add explicit optional-engine focused repair checks with independent full-target
  evidence, resumable scoped proof journals, exact failure explanations, immutable
  verification baselines and regression comparisons through CLI and MCP.

- Add explicit managed workspace verification with complete per-target reports,
  successful proof receipts, and verification-context isolation. Linux supports
  precise missing-configuration observation; macOS remains conservative and may
  reverify after unrelated directory activity.
- Add persistent local verification jobs, background submission, status/results,
  cancellation, diagnostics, and workspace-aware watch and MCP job tools.
- Add optional authenticated HTTP shared-cache reading and signed publication,
  private connection settings, and a deployable local/private team server.
- Record complete frontend-reuse acceptance, full local conformance and measured

- Add feature-scoped Singular source builds, validated runtime identities, and

  pinned memory allocator.

- Keep portfolio mode and seed provenance in compact MCP result lookups and
  summaries. Unknown summaries no longer infer an unobserved resource failure.

- Failing crates with incomplete attribution no longer confirm successful
  timing entries that may hide bit-vector failures (VI-0003). They report
  uncertainty while preserving Verus's raw fields and diagnostics. MCP retires
  old persisted result records; reverify to establish current results.

- `sail bench` runs the installed workload tool with unchanged arguments and
  standard streams.

- Fresh fragility measurements force reverification in a locked Sail-owned
  target, preserving the caller’s Cargo artifacts and dependency compilation.

- Join fragility captures to functions by exact transcript hashes and check
  order; expose conservative function scores in JSON and MCP on request.
- Require reports for every requested verifying Cargo target before accepting
  a portfolio proof; reject ambiguous or unsupported target coverage.

- Exercise a real seeded proof, cold and warm, in the fast end-to-end check.
  Bound daemon readiness to sixty seconds and fail early when the daemon exits.

- Exclude skipped timing successes from function-scoped reports and portfolio
  acceptance (pinned Verus issue VI-0009).

- Explicit complete-run seed portfolio mode, retained attempt evidence, MCP
  selection, and isolated protocol-v4 cache namespaces (ADR 0020).

- Avoid adding a second progress-suppression flag to the deep suite example
  that supplies it itself. Verification arguments remain identical on both sides.

- Exclude overlapping deep suites and source rebuilds with exclusive build
  ownership; reject concurrency before materialized input cleanup.

- Deep tier: Verus's own `rust_verify_test` suite (4,695 tests) runs
  plain and through `sail-z3`, test by test (ADR 0019).
  - `cargo xtask build-verus-source` builds the pinned Verus commit from
    source with vargo, the pinned z3 and toolchain, under
    `<cache>/verus-src-build/<commit>`, and prunes it to what the tests
    need.
  - `sail-conformance rust-verify-test [--filter S]... [--every N]
    [--jobs N]` compares outcomes, exit codes and diagnostics, classifies
    plain-Verus flakiness separately, and exports a reproduction for each
    difference.
  - `ci/run.sh deep-rvt [cache]` (local-only) runs both, optionally also
    with the cache daemon.

- Preserve solver stderr during cached verification. Publish replies only after
  a clean, silent session completes; warning sessions always re-solve. Refuse
  older daemon and cache formats that could suppress diagnostics.

- Required `CI completion` rejects failed, cancelled and skipped gates,
  including CI image failures. Branch protection requires an updated branch;
  every CI job now has at most ten minutes.

- A shared cache tier (ADR 0017, `docs/trust.md`). Its entries are signed
  with ed25519 and verified before use. Each signature binds the key, the
  reply hash, the command, the solver identity, the platform class, the
  effort and the format version.
  - `sail serve --shared DIR` (`SAIL_SHARED_STORE`) consults the store on
    local misses, with a 250 ms timeout (`SAIL_SHARED_TIMEOUT_MS`) and a
    back-off after a timeout. Verified hits are copied locally with
    provenance `shared:<key id>`. Every failed check is a miss. Entries
    for another solver or platform class are refused and counted.
  - `sail cache keygen --out FILE`, `sail cache trust add|list|remove`,
    and `sail cache publish --to STORE --key FILE [--filter ...]
    [--dry-run]`. Only local pinned-solver entries are published: never
    shared copies, and never `unknown`s the serving policy would not serve.
  - `STATS` gains `shared_*` counters and `INFO` a `shared` section;
    `sail status` shows both. The protocol version is unchanged.
  - The daemon now records each session's solver identity in the entries it
    stores. Entries stored earlier are not published.
- `sail mcp`: an MCP server on stdio (`docs/mcp.md`, ADR 0016). Its tools:
  - `verify`: a crate, module or function, through `sail verify --output
    json`;
  - `counterexample`: models and diagnostics from the latest run;
  - `cached_result`: the latest known verdicts, with when and how they were
    established and whether the sources changed since;
  - `fragility`: opt-in, exact captured-query replay with conservative
    per-function scores and explicit unavailable attribution.

  Calls can be cancelled. Results are kept per project under
  `<cache>/mcp`.
- `sail verify --output json`: one schema-v1 JSON document on stdout
  (`docs/output-schema.md`, ADR 0014). It has per-function verdicts with tier
  and provenance, and per-obligation results with stable identities, effort,
  cache sources and counterexample models. It also carries Verus's
  diagnostics as data. stderr and the exit code are unchanged.
- `sail-z3`: with `SAIL_PROVENANCE_DIR` set, a cached session records how many
  replies the cache served (ADR 0014).
- `sail status [--json]`: the daemon's versions, uptime, cache root, log,
  disk and memory tiers, write queue and counters. Exits 4 (`SAIL0401`)
  when no daemon is listening (ADR 0015).
- `sail cache stats|verify [--remove]|gc --max-bytes N|clear --yes`, on the
  daemon's cache root or `--cache DIR` (ADR 0015).
- Daemon: an in-memory tier in front of the disk tier
  (`--memory-bytes`, `SAIL_DAEMON_MEMORY_BYTES`, default 256 MiB). `PUT`s
  are written behind, through a bounded queue drained on shutdown. The
  daemon stops after 30 minutes without connections
  (`--idle-timeout`, `SAIL_DAEMON_IDLE_TIMEOUT`), logs to
  `<cache root>/daemon.log`, stops cleanly on SIGINT, SIGTERM and SIGHUP,
  and removes its socket on exit.
- Daemon protocol: an `INFO` operation; `STATS` reports `memory_hits` and
  `dropped_puts`. The protocol version is unchanged (ADR 0015).
- `sail watch [ARGS...]`: re-runs `sail verify` as sources change. Edits
  cancel the run in flight and restart it once they settle.
- `sail fragility`: opt-in fragility measurement. Runs `cargo verus verify`
  once through `sail-z3` in pass-through with tracing, then re-runs every
  captured solver session under N configurations of the same pinned Z3
  (reseeds, and optionally semantics-preserving assertion shuffles), and
  reports per-check answer and effort distributions, the share of the
  rlimit used, stability classes and scores (`--json` for the full
  report; `--output json` also works). Partial selections run
  `cargo verus focus`. It changes no verdict and never touches the cache
  (ADR 0018). The MCP `fragility` tool now runs it.
- `sail-bench fragility`: the fragility census over corpus units, written
  to `bench/results/fragility-census-*.json` and rendered by
  `sail-bench report` (ADR 0018).
- `sail verify`: runs `cargo verus verify` with the same arguments, through
  `sail-z3` and the cache daemon (started on demand).
- `sail-bench warm` and `sail-bench edit`: the warm (no change) and
  single-function body and specification edit workloads, each run against a
  fresh `sail serve` with conformance checked on every sail run. Edits come
  from `corpus/edits.toml`. `sail-bench report` renders both (ADR 0012).
- Daemon protocol: a `STATS` operation reporting the daemon's counters
  (ADR 0012).
- `sail serve`: the daemon, serving a local disk cache over a Unix socket.
  `sail-z3` with `SAIL_DAEMON_SOCKET` set serves replies from the cache and
  starts the pinned Z3 only on a miss, replaying the whole session prefix
  (ADR 0011).
- `SAIL_DAEMON_TIMEOUT_MS`: the shim's daemon client timeout (default
  10,000 ms).
- `sail-z3` in cached mode exits when its solver dies, as pass-through does,
  instead of waiting for stdin to close. A reply cut short by the solver's
  death is never stored. Fault-injection tests: `docs/fault-injection.md`.
- Workspace skeleton, CI fast tier and AI-authorship guard.
- `sail-z3`: a pass-through Z3 shim for Verus (`VERUS_Z3_PATH`), with an
  optional trace tap (`SAIL_TRACE_DIR`).
- `cargo xtask fetch-verus`: installs the pinned Verus release.
- `sail-bench profile|seeds|history`: query-time profile, seed stability and
  history-dependence analyses over shim traces.
- `sail-conformance`: `cargo-verus` corpus units (with Verus dependencies
  patched to the pinned source in a scratch copy), project requirements
  (skipped and reported when unavailable), and the standard-tier corpus.
