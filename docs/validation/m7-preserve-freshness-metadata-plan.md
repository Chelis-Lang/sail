## Change and authority

Linux publication of the context runtime `.link`, `input-state.json`, local
`source-inputs.json` and local `build-inputs.json` first serializes with the same
original serializer. A no-follow, nonblocking regular-file read compares every
byte and requires exact length, EOF, a singly linked private 0600 file and equal
before/after named and opened identities, including inode, device, ownership,
mode, size and nanosecond change/modify times. Comparison uses a fixed 16 KiB
stack buffer, one descriptor and at most the serialized length plus one byte;
it does not allocate another complete document or retain an equality memo.
Errors, uncertain identity, aliases, changed bytes and non-Linux platforms use
the original create-new temporary file, write and atomic rename. Special mode
bits also refuse the no-op route. Equivalent JSON spelling is insufficient.

The successful comparison is the no-op publication's observation point. It is
not an input authority. Concurrent changes after that point remain possible,
just as after the original rename. Existing independently acquired native
namespace and kernel lease barriers still reject those changes before Current
or digest reuse. The helper neither renews a dirty owner nor skips those barriers.

Freshness establishment already attempts the same retained RuntimeValidation Arc
and clean observer before cold fill. Avoiding needless same-byte replacements
can preserve that continuous owner for the same exact context/environment and
unchanged inputs. A real source edit still invalidates the previous owner;
preserving metadata alone cannot establish repair-edit speed or avoid its cold
fill. Any changed declaration, input, runtime, namespace or helper state still invalidates
it; a new context remains cold. No metadata-only Current shortcut, parsed graph
cache, asynchronous Completed status or detached fill is added. Completion still
waits for original synchronous independent freshness establishment.

Compiler-family generation consumption and export publication keep the original
transaction. Proof receipts, report publication, per-run runtime configuration,
content-addressed runtime identity creation and all proof/currentness keys are
unchanged. Executable/helper/sysroot/probe work in context construction also
retains its existing behavior. The candidate addresses only avoidable owner
invalidation, not every whole-loop or cold-start cost.

## Controls and sensitivity

Nine new source controls remain uncompiled:

- Exact unchanged multi-chunk bytes preserve inode/time; changed or differently
  spelled JSON, growth, absence, symlinks, hardlinks and nonprivate modes use
  original publication/error behavior. A deterministic same-byte name replacement
  after the real byte/EOF read refuses the no-op before its final identity checks.
- A real FreshnessIndex establishes native coverage, republishes all four actual
  sidecars, then requires the same retained RuntimeValidation Arc and revision.
- The explicit original atomic publication variant requires a different native
  owner even when bytes and input revision are equal.
- Restored runtime/source writes, exact-byte link aliases and stopped lease
  helpers refuse the original owner after metadata publication. Another context
  or environment receives no populated entry from the retained owner.

mandatory. No new background threads, cancellation channel or shutdown lifecycle
