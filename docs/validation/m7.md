# M7 validation record

This page condenses the M7 acceptance evidence for
[ADR 0027](../decisions/0027-interactive-proof-engine-and-repair-workflow.md)
and the [roadmap's M7 exit](../ROADMAP.md#m7-interactive-proof-engine-and-repair-workflow-in-progress).
It has one table per acceptance gate: the current status, the best evidence and
an indexed list of failed or interrupted attempts. M7 is **not accepted**.

**Environment.** Unless a row says otherwise, every local result below ran in
the Linux amd64 CI image under Docker emulation on an arm64 Mac, often under
concurrent development load. The rescue treats emulated runs as non-reference
for performance: their latency and wall-time numbers are diagnostic only, and
reference measurements must be repeated on a native x86-64 Linux host
(`scripts/perf-host.sh`, [ADR 0038](../decisions/0038-m7-rescue.md)). "Native
CI" means GitHub Actions on x86-64 Linux.

**Raw evidence.** Raw logs and archives are kept outside the repository and are
cited by SHA-256; the loose pre-rescue evidence is one archive with sha256
`c281800ad3c42f39a71745961fc6a44a8ad327caca73df7274f55a86316317a9`. The individual per-run records that these tables summarize
(about 650 files under `docs/validation/`, `bench/validation/` and
`engine/verus/candidates/`) are preserved unchanged in the git tag
`archive/m7-contracts-f7103bf`, at the same paths. The pre-M7
`bench/validation/` summaries were removed later (rescue L14) and archived
with sha256 `dcf30c1827434a157d17d15825305cdb8eac1265e99642489f8f37b97887322c`.
