# Sail 0.2.0 candidate release notes

Candidate for owner review; final publication is not approved. The registry
prerelease `sail-solve 0.2.0-rc.1` is published and independently installed on
Linux and macOS. Stable `0.2.0` packages and archives are being qualified.
See the [candidate record](../validation/stable-candidate.md) for exact sources,
artifacts, completed checks and remaining gates.

## Work on a proof without creating a Cargo project

Verify an existing Verus file, watch it while editing, or send it to an MCP
client. Successful unchanged proofs retain their establishing provenance;
changes to sources, includes, environment or runtime invalidate reuse.

```sh
sail verify proof.rs
sail verify proof.rs --output json
sail watch proof.rs
sail repair-check proof.rs --function proof::lemma --engine interactive --output json
```

Repair checks a selected function first and independently verifies the complete
file before accepting the repair. A partial result remains provisional. Durable
jobs and MCP accept the same file workflow. See [standalone verification](../standalone-verification.md)
and [proof repair](../proof-repair.md) for selectors and supported configurations.

## Prepare the next call after returning

After successful Cargo verification, the daemon can prepare an unchanged call
in the background. `sail new` can start project verification after returning.
Foreground work takes priority; edits invalidate old preparation and queued
work checks its origin before running. Preparation uses additional CPU and disk
and may not finish before an immediate call. Disable it with
`SAIL_BACKGROUND_PREPARE=0`. See [background preparation](../background-preparation.md).

## Manage disk use and share CI caches

Opt in to a managed-project byte budget, inspect its status or prune to a byte
target. Busy workspaces and the newest workspace remain protected, so the cap
is soft. Budgets are disabled until configured. The [workspace guide](../workspace-verification.md)
describes `sail cache projects budget` and `prune --to-bytes`.

The [CI-cache walkthrough](../ci-cache.md) covers separate solver and managed
caches, restored-run validation and invalidation after edits or toolchain
changes. The installable [consumer skill](../../skills/sail-verification/SKILL.md)
provides the corresponding agent workflow.

## Install through Cargo

The package name is `sail-solve`; its executable remains `sail`. It installs
its companion solver shim, and `sail engine install` downloads and validates
the pinned runtime. The published prerelease can be installed now:

```sh
cargo +1.99.1 install sail-solve --version 0.2.0-rc.1 --locked
sail engine install
```

The two native archive platforms remain Linux x86-64 (glibc 2.39+) and Apple
silicon macOS. Archives include their runtime and preverified vstd bundles;
Cargo installations establish their own proofs. These are different first-use
paths. See [installation](../install.md).

## Correctness and runtime changes

The pinned Verus fork now records actual compiler-returned binary include bytes.
Unchanged standalone proofs can retain Current binary-input receipts; same-size
changes with restored mtime require verification. The composed runtime's source
suites and exact-input controls cover both platforms. Solver and verdict
contracts remain in force, including the existing bounded compiler-visible
integration-settings exception in ADR 0088.

Preparation and service probes now have bounded connection establishment;
service faults retain the pinned-solver fallback. Generated-input closing
revisions, queued edits and actual idle-budget eviction have independent
regression controls. See the [changelog](../../CHANGELOG.md).

## Performance and remaining limits

The qualified core composition measures all 23 workflow rows and complete Vest,
IronKV and CapybaraKV mutation catalogues in six paired rounds on both platforms.
Its source/runtime identity and complete raw streams are recorded separately
from the final versioned archives. Corrected benchmark interpretation and every
slower case remain explicit in [feature qualification](../validation/release-expansion.md).
These measurements do not establish universal speedups.

First unchanged calls and calls that miss replay still pay full-path overhead.
Tiny edits/reverts remain slower, and the latest Mac Anvil cold median is
98.94 s against stock's 96.87 s. The source/per-file digest prototypes remain
disabled because they showed no general whole-call gain. Watch's standalone
sources must stay under its working directory; partial checks remain partial.
See [known issues](../known-issues.md) for the complete limitations.
