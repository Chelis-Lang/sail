# Sail 0.3.0 release notes

Published as attested Linux/macOS archives and the crates.io package
`sail-solve 0.3.0`. The executable remains `sail`. See the
[GitHub release](https://github.com/Chelis-Lang/sail/releases/tag/v0.3.0) for
downloads and the [changelog](../../CHANGELOG.md) for the complete list of
changes.

0.3.0 removes API that 0.2.0 published, so it is a breaking release for Rust
and wire clients of the removed surfaces. Default `sail verify` output,
verdicts and diagnostics are unchanged.

## Native TLA+ model checking (experimental)

Sail now links D.I.V.E. 0.1.0 (`dive-api` and `dive-ir` from crates.io) and
runs it in the isolated `sail-runtime-worker` process
([ADR 0172](../decisions/0172-native-temporal-in-main-workspace.md)). Submit a
temporal job through `sail runtime execute`, MCP `runtime_execute` or the
`sail-dive` Rust client. A job carries a closed set of TLA+ modules and a
configuration, and asks for exhaustive checking, finite simulation or trace
validation.

- Safety and genuine temporal properties both run with an exact state store,
  seed zero, one worker and the job's state and depth limits.
- A property holds only with complete exploration evidence; for temporal
  properties that is a completed graph capture.
- A refutation carries a counterexample that D.I.V.E.'s independent trace
  validator has accepted.
- A state or depth limit returns `Stopped`, which makes no claim about the
  model. Simulation returns sampled traces, never a proof.
- Only the embedded `Naturals`, `Integers`, `Sequences`, `FiniteSets` and
  `Bags` modules are admitted besides the job's own files. Host-capable
  modules (`TLC`, `Json`, `Randomization`) and bundled CommunityModules and
  TLAPS sources are refused.

Release archives ship the worker with its installation manifest, so
`sail runtime capabilities` reports temporal checking installed. `cargo
install sail-solve` installs the worker binary but not the manifest, so a
Cargo installation reports it not installed. See
[native temporal jobs](../temporal-jobs.md) and the
[shared runtime](../runtime.md#native-temporal-jobs).

## Proof health

`sail health JOB` and MCP `proof_health` read the recorded per-check solver
effort of a completed job or a saved `sail verify --output json` document,
ranked by resource exhaustion and checks near their limits. They run no
solver and change no verdict. Missing effort is reported as unavailable, not
zero. See [proof health](../proof-health.md).

## CI reports and the GitHub Action

`sail report --format github-summary|github-annotations|sarif` renders a
saved `sail verify --output json` document for CI without verifying again;
`--baseline FILE` adds what changed against an earlier document. See
[CI reports](../ci-reports.md).

The GitHub Action (`uses: Chelis-Lang/sail/action@v0.3.0`) installs the
release with its attestation checked, restores and saves solver replies, proof
receipts and Cargo downloads, runs `sail verify --output json`, writes the
summary, annotations and SARIF, and ends with `sail verify`'s exit code. 0.3.0
is the first release it works with. See [GitHub Action](../github-action.md).

## Other changes

- A result that is not Current names the failing currentness predicates in its
  `SAIL3114` note and in a `currentness-decision` job event.
- A run after an interrupted first run of the same setup verifies as a first
  run instead of reading Unknown (#696).
- The shipped vstd proof applies to projects whose target directory also holds
  crates outside vstd's dependency closure, such as CapybaraKV (#563).
- Instant revert survives an edit that lands while background preparation is
  running (#595).
- `sail jobs result` leads a failing target's line with its failures and says
  when compilation or Verus stopped before any function was checked.
- The MCP `counterexample` tool returns `decoded_inputs` from the solver's
  model. Decoded values are never presented as a validated counterexample.
- `sail runtime` and the MCP runtime tools are part of the supported command
  set.

## Removed

- The neutral-contract surfaces: the `sail-contracts`, `sail-contracts-macros`
  and `sail-contracts-ir` crates, neutral source jobs, neutral mutation and
  literal witnesses ([ADR 0109](../decisions/0109-oyster-retired-v030-scope.md)).
  The last commit that contains them is tagged `archive/neutral-contracts-final`;
  the published 0.2.0 crates stay on crates.io and are not yanked.
- Requirement attribution: `--requirement`, `sail assurance` and MCP
  `requirement_assurance`
  ([ADR 0148](../decisions/0148-retire-active-requirement-attribution.md)).
  Retained job records stay readable; see
  [retirement](../requirement-assurance.md).
- The separate temporal extension workspace with its `sail-temporal` package,
  and the private-dependency credential that building it needed. Building,
  testing and publishing Sail needs no credential.

## Install

```sh
rustup toolchain install 1.99.1 --profile minimal --component rust-src
cargo +1.99.1 install sail-solve --version 0.3.0 --locked
sail engine install
```

The native archive platforms remain Linux x86-64 (glibc 2.39+) and Apple
silicon macOS. See [installation](../install.md).

## Limits

Native temporal checking is experimental and does not cache temporal evidence.
First unchanged calls and calls that miss replay still pay full-path overhead,
and some measured rows remain slower than plain Verus; see
[performance](../performance.md) and [known issues](../known-issues.md).
