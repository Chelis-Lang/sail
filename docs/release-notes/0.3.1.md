# Sail 0.3.1 release notes

> **Draft.** Every performance figure below is a placeholder until the S7

Published as attested Linux/macOS archives and the crates.io package
`sail-solve 0.3.1`. The executable remains `sail`. See the
[GitHub release](https://github.com/Chelis-Lang/sail/releases/tag/v0.3.1) for
downloads and the [changelog](../../CHANGELOG.md) for the complete list of
changes.

Sail 0.3.1 links D.I.V.E. 0.2.0 (`dive-api`, `dive-ir`, `dive-value` and
`dive-trace` from crates.io) and adds reuse across edits for native temporal
jobs: rechecks, edit sessions, replay of completed checks and rechecks of
saved counterexamples. Large simulations now return the traces that fit the
response bound instead of failing. Default `sail verify` output, verdicts and
diagnostics are unchanged.

## Temporal checking on D.I.V.E. 0.2.0 (experimental)

- Native temporal jobs link D.I.V.E. 0.2.0 and accept its report schema 4.
- Native witnesses can carry TLA+ model values through checks, simulations
  and independent trace validation. Older encodings and request hashes remain
  readable.
- Jobs can check pure TLC function updates, finite permutations and the pinned
  finite-set utilities that SlateDB uses.
- A simulation whose evidence exceeds the 16 MiB response bound now runs:
  D.I.V.E. samples every trace, and the response keeps and independently
  replays the lowest-numbered traces that fit, counted in
  `statistics.traces_kept`. A 1,000-trace, depth-100 bosco job returns 80
  replayed traces in a 15 MB response, where 0.3.0 failed with `SAIL4210`.
  `SAIL4216` now means not one trace fits (#767).

## Reuse across edits

See [native temporal jobs](../temporal-jobs.md#rechecking-and-undo).

- Completed native checks and validated refutations replay after identical
  reruns and undo; results name the matched key. Supporting installations can
  prepare the first check in the background and carry signed receipts between
  CI jobs (#774).
- `sail runtime recheck` retains a completed proof across a project edit that
  leaves the resolved module bytes and selected configuration unchanged,
  rechecks a named invariant counterexample after an equivalent CFG edit, and
  can certify the first of several temporal properties alone.
- `sail runtime edit-session` checks successive versions with one
  authenticated worker. Edited safety invariants can reuse ordered states, and
  edited temporal properties can reuse a complete labelled graph.
- `sail runtime witness-recheck` rechecks a saved temporal counterexample
  against edited source with an installed `dive` executable, falling back to
  ordinary checking, and discovers saved witnesses for an edited job.

## Not in this release

`sail runtime symbolic-check` and its strategies are not listed in `sail help
runtime` or the user guide. They need D.I.V.E.'s symbolic proof worker, which
D.I.V.E. 0.2.0 does not ship, and are planned with D.I.V.E. 0.3
([#805](https://github.com/Chelis-Lang/sail/issues/805)).
[Symbolic rechecks](../design/symbolic-check.md) are not in this release.

## Install

```sh
rustup toolchain install 1.99.1 --profile minimal --component rust-src
cargo +1.99.1 install sail-solve --version 0.3.1 --locked
sail engine install
```

The native archive platforms remain Linux x86-64 (glibc 2.39+) and Apple
silicon macOS. See [installation](../install.md).

## Limits

Native temporal checking remains experimental. Verus mutation testing, proof
profiling, the Kani and cvc5 backends, simpler installation and an editor
bridge are planned for 0.4.0 ([roadmap](../ROADMAP.md)). See
[performance](../performance.md) and [known issues](../known-issues.md).
