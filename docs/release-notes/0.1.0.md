# Sail 0.1.0 release notes (draft)

Status: draft. 0.1.0 is not released or tagged. Release candidate
`0.1.0-rc.7` (`8797ccd4`) passed qualification on Linux and macOS
([#282](https://github.com/Chelis-Lang/sail/issues/282),
[record](../validation/release-candidate.md)). The full change list
is in the [changelog](../../CHANGELOG.md).

## What Sail is

Sail makes Verus verification loops faster for developers and coding agents.
`sail verify` takes the same arguments as `cargo verus verify` and prints the
same output. Behind it, Sail:

- caches Z3 answers across edits;
- reuses a preverified vstd for matching projects;
- reuses proofs of unchanged targets;
- restores a previous proof when you undo an edit.

In default mode, Sail gives the same per-function verdicts, diagnostics and
exit codes as stock Verus with its pinned Z3, with one accepted, bounded
exception: code that reads Sail's named integration settings sees them
([ADR 0088](../decisions/0088-compiler-visible-integration-settings.md); see
[known issues](#known-issues)). When any part of Sail fails, it falls back to
the pinned Z3 and the result stays correct.

## Platforms and pins

- Linux x86-64 (glibc 2.39 or later) and macOS on Apple silicon.
- Prebuilt archives contain `sail`, the solver shim `sail-z3` and Sail's
  Verus: Sail's [Verus fork](https://github.com/Chelis-Lang/verus) runtime
  `47fb3be6`, based on upstream Verus `0.2026.10.18.7d82994`, with the pinned
  Z3 4.16.0 and the proof-repair engine. You do not need a separate Verus install.
- Proof reuse needs Cargo 1.93.0 to 1.99.1
  ([ADR 0084](../decisions/0084-qualified-cargo-range.md)). Other Cargo
  versions still verify correctly, with solver caching but without proof
  reuse (`SAIL3112`/`SAIL3139`).
- Install with `scripts/install.py --version 0.1.0 --install-toolchain`. It
  checks the archive's checksum, validates the bundled runtime and, when
  GitHub CLI is signed in, verifies the archive's build-provenance attestation.
  See [install](../install.md).

## Highlights

- **Unchanged calls replay**
  ([ADR 0082](../decisions/0082-unchanged-call-replay.md)). When nothing
  changed since a Current run, `sail verify` prints that run's output without
  running Cargo, in 0.03–0.09 s. It checks a complete stat-stamp vector of the
  inputs, the target, the tools and the declared variables before replaying.
  This now also works on macOS. `SAIL_MANAGED_NOOP=0` turns replay off.
- **Faster edits, fixes and reverts.** Sail reuses receipts for unchanged
  targets and replays the solver for unchanged queries. Undoing an edit
  restores the original proof: up to 16 revisions per target, with the first
  verified revision pinned.
- **Fail → fix after a focused run no longer rebuilds the dependency graph.**
  On Anvil, the fix step drops from 75 s to 51 s.
- **Same stderr as stock.** Human `sail verify` stderr now matches plain
  `cargo verus verify` byte for byte. Sail's own notes (`SAIL0003`,
  `SAIL3112`, `SAIL3138`, `SAIL3146`) appear in `--output json` and with
  `SAIL_EXPLAIN=1`.
- **Promoted features:** proof repair, proof and evidence tools, and the MCP
  server for agents. Fragility, the portfolio and the team cache stay
  experimental.
- **No private dependencies in the main build.** Native temporal jobs, which
  need D.I.V.E., moved to a separate extension workspace
  (`extensions/temporal`). Release archives report temporal jobs as
  unavailable.

## Correctness fixes in this release

Cache and solver stream:

- A cached reply is served, stored or kept only when it is exactly one
  complete response frame (#379).
- A `check-sat-using` gives one response (#397).
- After a cache fallback, the pinned solver's replay is compared with every
  reply already served. A difference stops the session with `SAIL2005`.
- A cached session's buffer is capped (`SAIL_SHIM_BUFFER_BYTES`, default
  256 MiB). Above the cap the session continues as exact pass-through.
- Creating a cache temp file can no longer truncate an existing symlink
  target (#412).
- Daemon fixes: the LRU tick (#474) and the queue-wait overflow (#478).

Input capture:

- Dep-info and environment names are decoded exactly (#408, #383).
- An unreadable declaration provider fails closed instead of counting as
  empty coverage (#382).
- A digest-cache hit keeps the requested alias binding (#381).
- Read-back is bracketed by stamps (#387).
- Forwarded workspace words no longer widen Cargo's target selection
  (#467).
- `option_env!` and `include!` reads inside ghost code are now tracked as
  inputs (#386, #439).
- A missing or malformed artifact journal or source-input record counts as
  incomplete coverage, so that run verifies again (#377).

Proof reuse:

- Sail's managed environment and `--time` injection no longer change
  verdicts. Sail's Verus options travel outside the compiler argv, so the
  compiler sees the same argv as under plain cargo-verus (#385, #393).
- Tool identity is content-addressed, so restored targets and receipts are
  reused on a new CI runner (#421).
- Job status, MCP and repair report a stored result as Unknown, not Current,
  once the Sail, Verus, Cargo or rustc it was recorded against has changed.
- Compile-only runs are never treated as proof.
- On macOS, unchanged-call replay is now recorded even though Cargo copies
  build scripts (#437).
- Unchanged-call replay binds every environment variable the admitted proof
  receipts read, including variables read only in ghost code that Cargo's
  dep-info omits. Before, changing such a variable could replay the earlier
  verified report where stock fails. Older replay records are retired
  (#552, fixed by #554).

`sail watch`:

- No extra restart after Cargo's output write (#403).
- An edit is no longer missed when macOS drops native events (#416).

## Known issues

The full list is in [known issues](../known-issues.md). The main items:

- **The first unchanged call after a verification is slower than stock**
  (#232). It takes the full path and records the replay: Anvil takes 2.44 s
  against 0.36 s on Linux and 2.11 s against 0.30 s on macOS, and Vest and
  CapybaraKV about 0.6–0.8 s on both. Every later unchanged call replays.
- **macOS Anvil cold runs are about 0.9 s slower than stock** on a
  100-second run, with overlapping ranges (#232). Linux cold medians are
  faster on every measured project.
- **Sail's named integration settings are visible to compiled code**
  ([ADR 0088](../decisions/0088-compiler-visible-integration-settings.md),
  #435). `VERUS_Z3_PATH`, named `SAIL_*` variables and Sail's driver alias
  reach build scripts and the compiler. This is an accepted, bounded exception
  to stock equivalence (see [divergences](../divergences.md)). No ordinary
  project reads them, but code that does can differ from plain cargo-verus.
- **Proof reuse loses effective compiler-environment bindings** (#551).
  Ordinary receipt reuse and retained-proof admission both normalize the
  effective ` __VERUS_DRIVER_ARGS__` to its base value; ordinary receipts also
  miss `SAIL_PROVENANCE_DIR` and ghost-only reads of `SAIL_COMPILER_INPUTS`
  and `SAIL_COMPILER_INPUTS_BINDING`. This is a source-established
  input-coverage gap; no end-to-end wrong verdict is reproduced.
- **A forced run of a non-default profile fails instead of reverifying**
  (#553). After a verified `--release` run, `SAIL_MANAGED_FORCE=1 sail verify
  --release` ends Unknown with `SAIL3107`, because managed cleanup omits
  Cargo's profile and target selectors. No false proof results.
- **The shipped vstd proof is not used** when Verus flags other than a
  supported `--rlimit` are forwarded
  ([ADR 0060](../decisions/0060-shipped-vstd-under-a-raised-rlimit.md)), or
  when the toolchain has `rustc-dev` or `llvm-tools` (#252, #264). vstd then
  verifies normally.
- **A miss re-solves the whole bucket** (#158). Editing one function re-sends
  its module's whole solver session.
- **No single-file projects** (`verus file.rs`, #164), and only Sail's own
  Verus release is supported.
- **A concurrent edit that restores every stamp,** inode change time
  included, is not detected during read-back (#387).
