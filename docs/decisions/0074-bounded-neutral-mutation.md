# 0074: Keep bounded neutral-source mutation evidence separate from proof

## Decision

Add an opt-in, versioned mutation campaign to the existing neutral source job
service. Require an authenticated completely proved baseline with original tool
identity. Generate at most eight fresh source jobs under unchanged requirement
IDs, guarantees and preconditions. The first policy replaces only contracted
free scalar-return executable bodies with boolean or integer literals. Retain
unsupported targets and candidates omitted by the caller's budget explicitly.

The controller owns its submitted jobs, cancellation token, aggregate deadline
and joined thread. Every worker retains the existing process-group cancellation,
fixed deadline and stream bounds. A campaign never cancels a deduplicated job
owned by an ordinary source submission or another campaign.

Classify a mutant as killed only when the original stable, fully attributed
report contains a conclusive SAT verifier rejection of its mapped function,
with unchanged non-target proofs and no unknown, missing or unrecorded checks.
This means verifier rejection under the unchanged admitted contract. It does
not mean a concrete source-level counterexample. Whole-source proof is survived.
The target success flag is not failure-completion evidence: a rejected target
correctly has `complete = false`. Require its completed Verus verification
totals and explicit failed report exit status, accepting only the known direct
failure status or Cargo wrapper failure status at the enclosing process.
Compiler failures, missing totals and partial-scope reports remain inconclusive.
All other evidence, including generic NotProved, is inconclusive. A passing
campaign requires every policy candidate killed, with no unsupported, omitted,
unexecuted, survived or inconclusive scope.

Persist source, budgets, actual job identities and exact original worker
stdout/stderr through independently sealed baselines. Reauthenticate all links
and rerun deterministic generation on every service read. Restart, interruption
and pruning never synthesize a proof. Export complete original streams for
consumer retention; refuse evidence exceeding the aggregate response bound.
The backend-free API validates retained receipt relationships and recomputes
classifications. Native source admission, inventory completeness, translation
and actual backend execution remain the producing service's trust boundary.

Advance requirement assurance to version two for an attached bounded mutation
state. Old clients refuse negotiation. Attachment requires the same baseline
job, source, function and guarantee. It does not change any proof outcome,
evidence tier, currentness or requirement relationship. Merely reading proof
evidence never starts a campaign.

## Consequences

Mutation assurance measures sensitivity to the declared bounded body policy.
It does not establish requirement entailment, input feasibility, full behavioral
correctness, termination or exhaustive mutation coverage. Operational campaign
start time and raw backend metadata belong to the original receipt, outside
consumer semantic source identities. The policy is deliberately narrow; new
mutation families require new explicit admission and evidence semantics.
